What This Guide Is

This is Afterpath's living design system - the single reference for tokens, patterns, and component decisions across every product surface. It's not a static PDF. It evolves as we ship, with every entry tagged by maturity so you know what's decided and what's still open.

Maturity Model
LOCKED
Decided. Use as-is.
Final tokens and patterns. No modification without a dedicated design session. Don't fork silently.
DRAFT
In use, open to revision.
Exists in shipped artifacts but not formally locked. Use for consistency, but propose changes if needed. Track deviations.
OPEN
Needs a design decision.
Flagged gaps. Don't ad-hoc in a feature build. Bring to a design session with context. Each OPEN item includes discussion context.

How Global Tokens Get Applied

The Foundation and Surfaces tabs define the global design system - tokens and patterns that apply everywhere. This tab shows how specific product areas apply those globals. Each application section is an example, not a new set of rules. If a pattern here doesn't trace back to a global token, it should be promoted to the global system or flagged as a deviation.

Usage Rules
Check maturity before using
LOCKED = use directly. DRAFT = use, note deviations. OPEN = don't ad-hoc, bring to design session.
Reference tokens, not raw values
Use --text-1 not rgba(255,255,255,0.7). Ensures global changes propagate.
Application sections are examples, not rules
The global tokens are the rules. Application sections show how those tokens get applied in context.
OPEN decisions get their own session
Don't solve an OPEN decision inside a feature build. Flag, placeholder, schedule.
Locking requires sign-off
Moving DRAFT to LOCKED requires review of all instances and explicit sign-off.
Update after every design session
New decisions logged. OPEN items resolved. DRAFT promoted or revised. The guide is the living record.
